  Migration 0003

  Batch mode explicitly via op.batch_alter_table, independent of env.py's
  render_as_batch (which is SQLite-only anyway), so the migration is
  self-contained and correct on both dialects:

  def upgrade() -> None:
      with op.batch_alter_table("links") as batch_op:
          batch_op.add_column(sa.Column("expires_at",
  sa.DateTime(timezone=True), nullable=True))

  def downgrade() -> None:
      with op.batch_alter_table("links") as batch_op:
          batch_op.drop_column("expires_at")

  Existing rows get NULL automatically (nullable column, no default) — they
  remain non-expiring. Test extends test_migrations.py the same way 0002 was
  tested: seed a link on 0002, upgrade to head, assert the column exists and the
  row survives with expires_at IS NULL, downgrade to 0002, assert row still
  there and column gone.

  expires_at validation

  Mirroring validate_url (raw string in, validated value out, one domain
  exception for every failure mode — matches AC3 lumping "past, equal to now, or
  no time zone" into one 422):

  - CreateLinkRequest.expires_at: str | None = None — raw string, not a pydantic
    datetime, so all semantics live in one place instead of splitting across
    schema/service.
  - validate_expiry(raw, now):
    - None → returns None (no expiry).
    - Parse ISO 8601; malformed → InvalidExpiryError.
    - No tzinfo → InvalidExpiryError.
    - Convert to UTC; parsed <= now → InvalidExpiryError (past or equal-to-now
      both rejected — matches AC3's "in the past, equal to now").
    - Otherwise return the UTC-normalized datetime.
  - Called from LinkService.create_link(url, expires_at=None) as
    validate_expiry(expires_at, self._clock()), then stored on the new Link.
  - InvalidExpiryError → 422, standard shape, code invalid_expiry (new code,
    parallel to invalid_url).

  Assumption to confirm: error code name invalid_expiry — the brief doesn't name
  one; I'm proposing it for symmetry with invalid_url. Flag if you want a
  different code.

  Where the expiry check lives / injectable clock / boundary

  - LinkService gains a constructor param clock: Callable[[], datetime] = 
    lambda: datetime.now(UTC) (identical pattern to StatsService). Existing
    LinkService(...) call sites and unit tests are unaffected since it's a
    defaulted trailing param.
  - Same clock is used for both the creation-time future check and the
    redirect-time expiry check, so "now" is one concept throughout the service.
  - New method, deliberately not part of resolve() (which stays expiry-blind so
    details/stats keep working per AC5):
  def resolve_for_redirect(self, code: str) -> Link:
      link = self.resolve(code)
      if link.expires_at is not None and self._clock() >= link.expires_at:
          raise LinkExpiredError(code)
      return link
  - Boundary: now >= expires_at → expired (matches ADR-002 D3 exactly).
  - dependencies.py adds get_clock() returning the real clock lambda, injected
    into get_link_service, so integration tests can override it via
    app.dependency_overrides[get_clock] to hit the exact boundary
    deterministically (same override pattern already used for
    get_code_generator).

  Test-design note: boundary tests will use whole-second (no microsecond) fixed
  clock values to avoid any sub-microsecond round-trip precision differences
  between SQLite and Postgres.
