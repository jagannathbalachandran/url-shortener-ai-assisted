# T-04: Redirect and link details

## Intent
Resolve a short code: redirect browsers to the original URL, expose the link's
details through the API, and return 404 for codes that don't exist.

## Context
- Depends on: T-02 (repository lookup by code), T-03 (LinkService, response
  schema, app factory), ADR-001 D3 (302, not 301)
- Requirements: FR-2 (redirect), FR-3 (404 for unknown short codes),
  FR-4 (link details without redirecting); Security (no information leak
  about which codes exist or what shape they have)
- Plan: docs/plan.md T-04.1–T-04.3

## Scope
In scope:
- `GET /{code}` → 302 with `Location` set to the stored original_url
- `GET /api/v1/links/{code}` → 200 `{"code", "short_url", "original_url", "created_at"}`
  (reuse the T-03 response schema, not a new one)
- LinkService.resolve(code): look up the link; raise a domain error
  (e.g. LinkNotFoundError) when it doesn't exist; the route maps it to 404
- Code format check in the service: anything that isn't a 7-char base62
  string is treated as "not found" without a DB query
- Repository lookup by code, reusing the T-02 method (add it only if missing)

Out of scope:
- Click recording and analytics (T-06)
- Expiry (T-07)
- Custom JSON error format, health checks, rate limiting (T-05); for now
  404 uses FastAPI's default `{"detail": ...}` JSON body
- HEAD requests, custom aliases, deleting or updating links
- Converting existing T-03 routes to the Annotated style (separate follow-up)

## Constraints
- Layering per CLAUDE.md: route → service → repository; route handlers only
  translate between HTTP and the service
- The root-level `GET /{code}` route must not shadow `/docs`, `/redoc`,
  `/openapi.json` or any `/api/v1/...` route; register it last
- `Location` must be exactly the stored original_url, with no re-encoding
  or normalisation
- Redirect responses carry `Cache-Control: no-store` so browsers and proxies
  don't cache the redirect (needed later for accurate click counts)
- Codes are case-sensitive
- Route parameters use the `Annotated[...]` style (e.g. `Annotated[str, Path()]`,
  `Annotated[Session, Depends(...)]`); do not add entries to
  `extend-immutable-calls`
- No new dependencies
- Exception (decided during T-04 planning): non-ASCII characters in the
  stored URL are percent-encoded as UTF-8 in `Location`, since HTTP headers
  can't carry them raw; `unquote(Location)` equals the stored URL. Pure-ASCII
  URLs are sent byte-identical.

## Acceptance criteria
1. Existing code: `GET /{code}` returns 302, `Location` equals the stored URL
   exactly, and `Cache-Control: no-store` is set. Tests use a client with
   redirects disabled.
2. Existing code: `GET /api/v1/links/{code}` returns 200 with the same fields
   and values as the create response.
3. Unknown code: both endpoints return 404 with a JSON body, never a 500.
4. Malformed code (wrong length, non-base62 characters, empty): both endpoints
   return 404 (not 422), and no DB query is made (verified in a unit test with a
   fake or spy repository).
5. Case sensitivity: a code differing only in case from an existing one returns 404.
6. `/docs` and `/openapi.json` still return 200 after the root route is added.
7. Round trip: create a link via POST, then redirect via its code, and land on
   the submitted URL, including one with a query string and fragment.
8. Unit tests (service resolve, format check) and integration tests (both
   endpoints through to the DB), including the failure cases above.
