# T-02: Database layer

## Intent
Persist links durably behind a repository, with versioned schema migrations,
working on SQLite locally and Postgres in CI. No API endpoints yet.

## Context
- Depends on: T-01 (scaffold), ADR-001 (D1: 7-char codes, unique; D2: new code per create)
- Requirements: Portability (SQLite local, Postgres verified in CI);
  Security (config via environment, no secrets in code)
- Used by: T-03 (create), T-04 (redirect/lookup)

## Scope
In scope:
- Settings via pydantic-settings: DATABASE_URL (default: local SQLite file),
  BASE_URL (public short-link base, default http://localhost:8000)
- SQLAlchemy 2.x engine/session setup
- `links` table: id, code (unique, indexed, length 7), original_url (max 2048),
  created_at (timezone-aware UTC)
- LinkRepository: add a link; get a link by code
- Repository raises a domain exception (e.g. CodeCollisionError) when a code
  already exists, so T-03 can retry per ADR-001 D1
- Alembic set up; initial migration creating `links` (with working downgrade)
- CI: Postgres service container; tests run against Postgres in CI
- docker-compose.yml with Postgres for optional local production-like runs
- .env.example documenting the settings (no real secrets)

Out of scope:
- API endpoints, code generation (T-03)
- Clicks/analytics table (T-06), expiry column (T-07)

## Approved new dependencies
sqlalchemy (2.x), alembic, psycopg (binary) — with minimum version bounds.

## Constraints
- Layering per CLAUDE.md: repository is the only layer that touches the DB
- No DB-specific SQL; must behave identically on SQLite and Postgres
- Timestamps stored in UTC
- Schema created only via Alembic migrations (no create_all in app code)

## Acceptance criteria
1. With no environment variables set, the app config uses a local SQLite file.
2. Setting DATABASE_URL to a Postgres URL switches the database with no code change.
3. `alembic upgrade head` creates the `links` table; `alembic downgrade base` removes it.
4. Repository can save a link and read it back by code; unknown code returns None.
5. Saving a second link with an existing code raises CodeCollisionError
   (not a raw database error).
6. Tests cover: save/read, unknown code, duplicate code, migration up/down.
7. CI runs the full test suite against Postgres and passes on 3.12 and 3.13.
8. `python scripts/check.py` passes locally (SQLite).
