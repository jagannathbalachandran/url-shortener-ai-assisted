# T-01: Project scaffold and quality gates

## Intent
Create a runnable, quality-gated Python project that every later task builds on.
No application features: this task establishes the foundation and the rules.

## Context
- First task; no dependencies on other tasks.
- Developed on Windows (Python 3.13); must also run on Linux/macOS for reviewers and CI.
- Later tasks: T-02 adds the database layer; T-03 onwards add features.

## Scope
In scope:
- pyproject.toml (dependencies + tool configuration)
- scripts/check.py (single cross-platform quality gate runner)
- .github/workflows/ci.yml (CI running the same gates)
- CLAUDE.md (project conventions for AI-assisted work)
- A smoke test so the test suite runs
- README.md setup section (Windows + Linux/macOS)

Out of scope:
- Any API endpoints, business logic or database code
- Docker, database configuration, migrations (T-02)

## Constraints
- Python >=3.11 (developed on 3.13); CI on 3.12 and 3.13
- src/ layout, package name `shortener`, with a __version__ attribute
- Runtime deps: fastapi, pydantic v2, pydantic-settings, uvicorn
- Dev deps (optional extra `[dev]`): pytest, pytest-cov, httpx, ruff, mypy, pip-audit
- Ruff: lint + format; enable security rules (S) alongside defaults
- mypy: strict mode, covering src/ and tests/
- Coverage: fail if below 85%
- No dependencies beyond those listed; state any assumption explicitly

## Acceptance criteria
1. `pip install -e ".[dev]"` succeeds in a fresh virtual environment on Windows,
   and on Linux in CI.
2. `python scripts/check.py` runs these gates in order:
   ruff check → ruff format --check → mypy --strict → pytest with coverage → pip-audit
3. check.py stops at the first failing gate, prints which gate failed,
   and exits with a non-zero code; exits 0 only when all gates pass.
4. On the empty project, all gates pass.
5. Gate verification: deliberately introducing a lint error makes check.py fail
   at the ruff gate; reverting it makes check.py pass again (verified manually).
6. CI runs check.py on every push and pull request to main,
   on Python 3.12 and 3.13, and passes.
7. A smoke test imports `shortener` and asserts __version__ is set.
8. CLAUDE.md contains the conventions listed below.
9. README.md explains setup and running the gates on both Windows (PowerShell)
   and Linux/macOS (bash).

## Conventions for CLAUDE.md
- Layering: api → service → repository; no DB access or business logic in route handlers
- Type hints everywhere; mypy strict must pass
- Every change ships with tests; a task is not done until scripts/check.py passes
- Stay within the task brief; do not add endpoints, dependencies or features not asked for
- Never put secrets in code, prompts, logs or commits; configuration via environment variables
- Prefer small, reviewable changes; state every assumption explicitly
- Before writing code, list the files to be created/changed and any assumptions
